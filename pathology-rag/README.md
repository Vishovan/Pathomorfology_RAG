# pathology-rag: этап 2 (текст) и этап 3 (изображения)

Что делает: PDF-учебники и разрешённые веб-источники -> разбор (Docling, OCR ru+en) -> чанки по разделам
с метаданными (книга, глава, раздел, нозология, страницы) -> эмбеддинги bge-m3 -> Qdrant (LlamaIndex).

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # при необходимости PATHRAG_DEVICE=cuda
docker compose up -d            # Qdrant на :6333

# положите PDF в data/raw/textbooks/
python scripts/ingest.py pdf --dry-run      # только парсинг и чанкинг, смотрим статистику
python scripts/ingest.py pdf                # полный ингест
python scripts/ingest.py status
python scripts/search_check.py "морфология крупозной пневмонии"
```

Совет: начните с `--dry-run` на 1-2 книгах и откройте `data/processed/chunks/*.jsonl`:
проверьте, что заголовки и страницы определились верно, до дорогих эмбеддингов.

## Веб-источники

`configs/crawl.yaml`: краулер выключен. Чтобы включить источник, прочитайте условия сайта и поставьте
`enabled: true` и `tos_checked: true`, затем уточните `seeds`/`allow`. Краулер соблюдает robots.txt и делает паузу между запросами.

```bash
python scripts/ingest.py web --source pathologyoutlines --limit 5 --dry-run
```

## Идемпотентность

- Манифест `data/processed/manifest.json` хранит хэш файла: неизменённые документы пропускаются.
- Чанки кэшируются, так что повторная индексация не требует повторного парсинга.
- ID точек детерминированы, а при изменении файла старые чанки документа удаляются.
- `--force` переобрабатывает всё.

## Известные ограничения

- Поле `nosology` сейчас эвристика (самый глубокий заголовок раздела). Позже можно заменить LLM-разметкой.
- Индекс только плотный (dense). Гибридный поиск (bge-m3 sparse + dense) можно добавить позже.
- Код с Docling, Qdrant и эмбеддингами не запускался на реальных данных. Проверены чанкинг, парсинг HTML и чтение реестра.

# Этап 3: изображения («препарат -> описание»)

Для каждого изображения хранится запись: подпись, диагноз, окраска, увеличение, орган, источник (книга и страница
или URL страницы), путь к миниатюре. Поиск идёт по подписи и метаданным (вектор bge-m3, работает на ru и en).
Необязательно можно добавить второй канал: вектор самого изображения (PLIP), результаты объединяются через RRF.

Окраска, увеличение, орган и диагноз определяются эвристиками (регулярные выражения по подписи, ru и en).
Поле `diagnosis_source` показывает, откуда взят диагноз: `caption`, `heading` или `manual`. Проверяйте выборочно.

```powershell
# рисунки из учебников (отдельным проходом или вместе с текстом, один разбор Docling)
python scripts\ingest.py images pdf --dry-run
python scripts\ingest.py pdf --with-images

# веб-атласы (только после enabled + tos_checked в configs\crawl.yaml)
python scripts\ingest.py images web --source hist_ysmu_gp --limit 5 --dry-run

# WSI: только ссылки (и по желанию превью), слайды не скачиваются
python scripts\ingest.py images wsi-links --csv data\raw\wsi_links.example.csv --dry-run

python scripts\ingest.py status
python scripts\image_search_check.py "крупозная пневмония" --stain "H&E"
```

Сначала всегда `--dry-run`: смотрите `data\processed\images\*.jsonl` (проценты заполненных полей печатаются в консоль).

## Поиск по самому изображению (PLIP, по желанию)

```powershell
$env:PATHRAG_IMAGE_MODEL="vinid/plip"
$env:PATHRAG_IMAGES_COLLECTION="pathology_images_plip"   # если коллекция уже создана без вектора изображений
```

PLIP понимает только английский: для русских запросов канал изображений отключается автоматически,
остаётся поиск по подписям. Для русских запросов к картинкам позже добавим перевод запроса в узле агента.
Модели CONCH и UNI требуют доступа на Hugging Face; интерфейс (`embed_images`, `embed_clip_text`) можно переключить на них.

## Ограничения этапа 3

- Подписи из Docling бывают пустыми или склеенными с соседним текстом, особенно в сканах. Рисунки без подписи
  получают контекст из заголовка раздела; без обоих они пропускаются.
- Интерактивные вьюеры (path-anatomy.ru, edu.geotar.ru, WSI-платформы) обычным краулером не берутся:
  используйте CSV со ссылками.
- Парсеры сайтов общие. Структуру каждого атласа я не проверял, после `--dry-run` возможно придётся поправить `seeds`/`allow`.
- Для веб-источников `save_thumbnails: false`: картинка скачивается только для эмбеддинга и удаляется, в индексе остаётся ссылка.
